### 2-3. 놀이 ① 「경판 공방」(`conveyor`, 새 부품, 약 2.5분)
**규칙(결정)**
- 작업장 한쪽에서 **나무판(경판 재료)** 이 벨트를 따라 천천히 들어온다. 각 판 위에 지금 **상태 아이콘**(생나무 → 젖은 나무 → 삶은 나무 → 마른 나무 → 새긴 판 → 마구리 → 옻칠)이 보인다.
- 작업대는 6개(그림 + 이름): **바닷물에 담그기 · 소금물에 삶기 · 그늘에서 말리기 · 글자 새기기 · 마구리 달기 · 옻칠하기**(지금 `script.making.cards` 문장 그대로, 2-5 순서). 학생은 판을 **끌어서 그 판에 알맞은 다음 작업대에 놓는다**(누른 작업대 단추로 보내기도 같은 동작, 키보드 1~6으로 작업대 고른 뒤 스페이스).
- 맞는 작업대(= 그 판의 다음 공정)에 놓으면 판 상태 아이콘이 다음으로 바뀌고 작업 동작(담그기 첨벙 · 삶는 김 · 말리기 · 새기는 소리 · 마구리 · 칠하기)이 잠깐 나온 뒤 판이 벨트로 돌아온다. **공정을 건너뛰거나 틀리면 판이 튕겨 나와 제자리로 돌아오고**(먼지 · 글자 튐 "순서가 달라요") 힌트 한 줄.
- 끝 공정(옻칠)까지 마친 판은 **선반에 쌓인다**. 선반 숫자는 놀이 숫자일 뿐이다(8만 장이라는 수와 연결하지 않는다).
- **3파**(파 실패 시 그 파만 다시, `runRounds(..., { easyAfter: 2 })` 그대로):
  - 1파: 앞 3공정(담그기 · 삶기 · 말리기) 작업대 3개만 켜짐, 판 3개가 한 장씩.
  - 2파: 작업대 5개(+ 새기기 · 마구리), 판 4개가 시간차로.
  - 3파: 작업대 6개 전부, 판 5개가 동시에 흐름(옻칠까지 끝낸 판 3개 이상이 목표).
- 실패: 벨트 끝에 **판 3개가 놓친 채 닿으면** 그 파만 다시. 놓친 판은 사라지지 않고 다음 시도 때 처음부터.
- **두 번 실패하면 쉬운 모드**: 다음 공정 작업대가 반짝이고, 벨트 속도 0.7배, 파마다 판 1개 줄임.
- 기록: `{ firstTryCorrect, firstTryTotal: 2, easyModeUsed }` — 두 놀이(공방 · 노 젓기)가 각각 한 번에 통과했는지(결정; 지금은 순서 카드 1 + 인물 끼우기 포함 3이었음). 획 따라 그리기는 첫 시도 점수에 넣지 않는다(읽기 · 선택 단계와 같이).
- 사실 경계(검토 대상): 공정 순서는 S8(침지 → 삶기 → 건조 → 판각 → 마구리 → 옻칠)의 **전해지는 방법**이다. 놀이 안내문 첫 줄에 "경판을 만들 때 이렇게 했다고 전해져요."를 넣는다(안내 `guide`). 과학적으로 확인된 사실처럼 쓰지 않는다. 옻칠은 "벌레가 먹지 않도록 했다고 전해져요".
- 불길은 쓰지 않는다: 소금물에 삶는 솥은 **김(수증기)** 만(지금 `makeFire` 모닥불이 작업장에 있으면 그대로 두되 놀이 연출에 불꽃을 새로 넣지 않는다).

**부품 위치(결정)**: 새 파일 `chapters/kit/conveyor.js`에 `export function conveyor(ctx, { stations, boards, easy, scene, gauge })`. 기존 `chapters/kit/*`와 `ops.js`는 바꾸지 않고 `ops.js`의 `runRounds · talk · opsGauge · popText · shake · finale · savedGuardian · usePlayerFigure`를 import해서만 쓴다. CSS id `kit-conveyor-style`. 작업대 그림은 지금 `chapters/ch5/pictures.js`의 `MAKING_PICTURES`(6장 그림)를 재사용.

### 2-4. 획 새기기 (`traceGlyph` 유지, 결정)
- 지금 `core/minigame.js`의 `traceGlyph`와 `content/glyphs.js`(大 · 藏 · 經) 그대로 쓴다. 코드 · 자료 수정 없음(`tools/gen-glyphs.ps1`로 생성, 손으로 안 고침; 藏 17획 그대로).
- 위치: 공방 뒤 "경판에 글자를 새겨 봐요" 한 단계. **시간 단축**: 세 글자 중 **藏 한 글자만 필수가 아니라 3글자 모두 선택**(첫 화면에 "새겨 보기 / 건너뛰기" 두 단추, 건너뛰어도 장은 이어지고 별점에 영향 없음). 이유: 놀이 2개 + 삼별초 마무리 때문에 12분을 넘기지 않기 위해, 손맛이 좋은 기존 부품은 살리되 필수는 아니게.
- 건너뛰기 단추는 `core/minigame.js`의 `traceGlyph`가 지원하지 않으면 **장 쪽**(`chapter.js`)에서 `traceGlyph` 호출 전에 `dialogue.ask`가 아닌 `ctx.ui`의 버튼 2개로 묻는다(카드 보기 아님). `core/minigame.js`는 수정하지 않는다.
- 안내 문장(`carving.intro`)은 지금 문장 그대로(안내 `guide`).

### 2-5. 놀이 ② 「노 젓기 박자」(`rhythm`, 새 부품, 약 1.5분)
**규칙(결정)**
- 삼별초가 **강화도 포구에서 진도로, 진도에서 제주로** 배로 옮겨 간 일을 한 바다 장면(고정 카메라, 배를 옆 뒤에서)에서 노를 저어 간다. 지금 6장의 "추격선에 잡히는 항해(`sailLeg`)"는 쓰지 않는다(몰기 + 추격은 불필요; 결정: 이 부분은 박자 놀이로 대체).
- 화면 아래 **왼 노 · 오른 노** 단추 두 개. 박자 링이 단추 위에서 줄어들어 가운데 표시와 겹칠 때 **알맞은 쪽 노를 누르면** 배가 한 번 앞으로 나간다. **왼 → 오른 → 왼…** 번갈아야 배가 곧게 가고, 같은 쪽을 연달아 누르면 배가 옆으로 돌아간다(조금 느려질 뿐 실패 아님).
- 박자는 1.0초(쉬운 모드 1.3초), 맞춤 허용 ±0.25초(쉬운 모드 ±0.4초). 한 구간(강화도 → 진도, 진도 → 제주) 각 **노 젓기 12번**, 구간 사이에 지금 컷 해설.
- 실패 없음 규칙(결정): 박자를 놓쳐도 배가 멈추지 않고 느려질 뿐이다. 한 구간을 **제한 시간 30초**(쉬운 모드 45초) 안에 도착하지 못하면 그 구간만 다시(`runRounds` 2번 실패 → 쉬운 모드, `easyAfter: 2`). 추격 · 잡힘 없음.
- 연출: 뱃머리 물보라 · 노 젓는 사람들(삼별초 군사 · 백성 실루엣)이 같이 젓는 동작(`core/figures.js`의 `push`/`carry` 중 가까운 동작 또는 위아래 흔들림만; 새 동작이 필요하면 `figures.js`에 **추가만**). 불길 · 피 없음.
- 기록: 구간 2개를 합쳐 한 놀이로 취급, 두 구간 모두 한 번에 도착했으면 첫 시도 성공.
- 새 문장 금지: 안내문은 규칙 설명 `guide`.
- 바다 무대: `chapters/ch5/scene.js`는 작업장을 짓고, **바다 무대는 새 파일 `chapters/ch5/sea.js`** 에서 `chapters/ch6/scene.js`(읽기 전용)의 배 · 바다 · 진도 · 제주 부두 모양을 참고해 새로 짓는다(`chapters/ch6/` 파일은 고치지 않는다). 무대는 작업장에서 떨어진 자리(`x 400` 방식, 끝나면 치움)에 지어 `ctx.fade` 사이에서 이동한다. 분위기는 `world.setMood('sea')`로 바꿨다가 퀴즈 앞에서 되돌린다(`ch4`가 `setMood('overcast')`로 되돌리는 방식).

**부품 위치(결정)**: 새 파일 `chapters/kit/rhythm.js`에 `export function rhythm(ctx, { beatSeconds, windowSec, strokes, seconds, easy, scene })`. 기존 kit은 불변, `ops.js` 함수만 import. CSS id `kit-rhythm-style`. 새 파일이므로 배포 때 `PRECACHE`에.

### 2-6. 삼별초 마무리 (장면 해설, 새 사실 금지)

### 5-3. 이어하기 · 옛 저장 처리 (결정)

- **옛 `ch5`만 마친 학생**: 새 6장 결과가 이미 있는 것으로 보이지만 삼별초 부분은 안 한 상태다. 결과 카드(`isSessionDone`)는 새 `ch5`가 "완료"라 3장(`ch3`) · 5장(`ch4`) · 6장(`ch5`)이 모두 끝났으면 뜬다. 결정: **허용**(별점만 옛 것). 새 장을 다시 하도록 강제하지 않는다.
- **진행 중 저장**(`save.data.current`): `{ id: 'ch6', stage }`는 목록에 없어 `core/main.js` 이어하기가 버린다(`redesign-review-2.md` 3절: 목록에 없으면 버림) → 학생은 장 고르기로 돌아간다. `{ id: 'ch5', stage: 'minigame'|'quiz' }`와 `{ id: 'ch4', … }`는 같은 id라 이어지며 각 `enterStage`가 새 장면을 안전하게 복원해야 한다(4절). `ch7`은 등록 전 저장될 수 없다.

## 7. 결정 기록 (선생님께 일일이 묻지 않음)
1. 6장 = 공방(`conveyor`) + 노 젓기 박자(`rhythm`) + 획 새기기(`trace`, 선택 · 건너뛰기 가능, 첫 시도 점수 제외). 지금 6장의 추격 항해와 인물 끼우기는 쓰지 않음.
2. 퀴즈는 2문항(대장경 까닭 + 근거지 옮긴 순서). 옻칠 · "끝까지 싸운 까닭" 퀴즈는 뺌.
3. 삼별초는 "삼별초 지휘관"(화자 id `baejungson` 유지, 이름표만 변경). 배중손 · 김통정 이름과 꾸민 대사 삭제.

5. 구성 변경은 모든 장 개발이 끝난 뒤 한 번에, 한 명이. ch7이 `load: null`인 동안은 "준비 중" 자리 + 건너뛰는 열림 규칙 + 결과 카드 5줄. ch7 등록은 S71 · S72 확인과 역사 검토 뒤에만.
6. 옛 `ch6`를 마친 학생도 새 6장을 다시 해도 됨. 옛 `ch5`만 마친 학생은 새 6장 완료로 취급.
