# 표준 작업 명세 — 고려 2장 「흥화진을 지켜라」 시범 (2026-10-26, 기획 담당)

> 근거: `redesign-plan.md` 3절 2장·5·7절·10절, `minigame-map.md` 결정(역사책 없음, 큰 장만 놀이 2개, 시안은 기존 그래픽 바탕), `redesign-review.md`·`redesign-review-2.md`, 승인된 시안 2판(b25a1e3: `core/figures.js`, `chapters/goryeo/set.js`, `core/hud-ops.js`, `tools/goryeo-style.html`). 이 명세 외 별도 기획 보고서는 쓰지 않는다.

## 1. 수정 목표
고려 2장(`ch2`)을 승인된 시안의 사람·성·화면 부품으로 다시 짓고, **성벽 지휘판(3파) + 백성 구출 호위** 두 놀이로 바꾼다. 같은 '지킴이' 한 명이 하고, 두 번 실패하면 저절로 쉬워지며, 한 장은 12분 이내, 필수 대사 7줄 이하다. 이 장이 끝나면 나머지 고려 장이 따를 **공통 틀**(놀이 뼈대·게이지·도장·흐름 이름)이 확정된다.

## 2. 수정 항목

### 2-1. 흐름 (이름만 바꾸고 `runChapter` 단계는 그대로)
- 출정 카드(해설, 기존 `intro` 2줄 유지) → 작전 준비(탐험 ≤2분) → 작전(놀이 2개) → 지킴 확인(퀴즈 2문항, 지금 것) → 도장·보상(30초).
- 체크포인트 이름은 `intro/explore/minigame/quiz` 그대로(저장 호환). 화면에 보이는 이름만 새 말로.
- **역사책 없음.** 사건 설명은 짧은 말풍선·안내판 2개(흥화진, 현종의 피란: 지금 `signHeunghwa`·`signNaju`)·퀴즈 해설로만.

### 2-2. 지킴이 (학생 인물)
- 편 내내 같은 한 명. 2장 시범은 **기본 생김새 + 간단 고르기 화면**(옷색 3가지 중 하나 고르기, 한 화면, 건너뛰기 가능). 선택은 기기 안 저장에 한 항목만 추가(기존 키를 바꾸지 않고 새 키; 없으면 기본값).
- 장면 안 옷은 이 장의 병사 옷(`GUARDIAN_OUTFITS`). 머리 위 작은 표시로 구분.

### 2-3. 작전 준비 (탐험, 필수 대사 줄이기)
- 성안을 걸으며 병사 3명을 성벽 구역(좌·중·우)에 **처음 배치**해 보는 짧은 연습(튜토리얼 겸용, 틀려도 불이익 없음).
- 대화는 머리 위 말풍선(한 번에 2줄 이하). 병사(거란 왕이 직접 왔다고 함, S3), 양규(흥화진은 압록강에 가까운 성, S2)를 만나 지휘판 열기.
- 안내판 2개는 선택 읽을거리(읽으면 보너스 별, 안 읽어도 진행). 백성(현종 나주 피란, S14)은 선택 말풍선.
- **필수 대사 합계 7줄 이하**(출정 카드 2줄 별도). 현종 약속·양규 전사는 놀이 뒤 마무리 대사 2줄(`script.result`, 지금 문장).

### 2-4. 놀이 ① 성벽 지휘판 (3파, 약 2분 30초)
- 성벽 북쪽을 **좌·중·우 3구역**으로 나누고, 학생은 병사 아이콘(3~4개)을 구역에 **끌어 놓는다**. 거란 병사가 놓인 구역에 사다리를 세우면 그 구역 병사가 사다리를 밀어낸다(`push` 동작). 병사 없는 구역에 닿으면 사다리가 꼭대기까지 오른다.
- 1파: 한 구역씩 느리게(병사 3명이 충분). 2파: 두 구역 동시(병사를 옮겨야 함). 3파: 세 구역 동시, 큰 사다리 하나는 병사 둘이 필요.
- 실패: 사다리 3개가 꼭대기에 닿으면 **그 파만 다시**. 성공하면 파마다 성벽 위 깃발 하나가 오르고, 3파 뒤 거란군이 물러난다(S15: 끝내 함락하지 못함).
- 조작: 터치 끌기와 키보드(방향키로 구역 선택 후 스페이스) 모두 가능. 버튼·병사 아이콘 크기는 손가락 기준(`tests/layout.test.js` 통과).
- 표시: 위 가운데 `createGauge`(지킴 게이지, 고려 대 거란), 남은 시간은 기존 위치. 성공·실패는 소리 + 화면 변화(먼지·흔들림·글자 튐).

### 2-5. 놀이 ② 백성 구출 호위 (약 2분)
- 지금 `rescue`(무리에 가까이 가면 구출)를 **호위**로 바꾼다: 지킴이가 무리에 닿으면 무리가 **뒤를 따라오고**, 성 쪽 안전선(깃발)까지 데려가면 구출 성공. 길목은 3갈래, 거란 호위병이 막는 길은 표시되어 학생이 길을 고른다.
- 무리 2개 → 4개 → 마지막 큰 무리. 지금 기준(시간 안에 네 무리 이상) 유지, 쉬운 모드는 속도·거리 완화.
- 폭력 표현 없음(밀기·물러남·넘어짐 없는 걷기와 놓침 표시만).

### 2-6. 실패·쉬운 모드·보상
- **두 번 실패하면 자동 쉬워짐**(지금 `runWithRetries`가 이미 3번째에 쉬운 모드. **2번째로 바꾸되 다른 장에 영향이 없게 장 쪽에서 옵션으로 넘긴다**; `runWithRetries` 기본값은 바꾸지 않는다. 기본값을 바꾸어야만 하면 변경 사실을 개발이 보고하고 다른 장 테스트를 돌린다).
- 놀이마다 `firstTryCorrect/Total` 기록(지금 형식 그대로, `{ firstTryCorrect, firstTryTotal: 2, easyModeUsed }`).
- 보상: 장 끝 `stampSeal`(도장, 별 1~3은 지금 `computeStars` 그대로), 지혜 카드 1장(수첩 연결은 지금 `ctx.notebook` 방식 재사용).

### 2-7. 장면·그래픽 (승인된 시안을 그대로, 새 그래픽 결정 없음)
- 장면: `buildHeunghwaSet`(`chapters/goryeo/set.js`)의 성벽·옹성·망루·사다리·깃발·기와집·장독대를 `chapters/ch2/scene.js`가 쓰게 한다. **밝기·눈송이는 그대로**(`SNOW_MOOD` 사용 여부는 시안 그대로).
- 사람: `core/figures.js`의 `makeFigure`/`guardianLook`/`crowdLook`(직업 옷 구분, 동작 `push/shoot/carry/cheer` 등). **`core/people.js`와 `chapters/kit/*`는 건드리지 않는다**(다른 29장이 씀).
- 놀이 카메라: 성벽을 대각선 위에서 내려다보는 고정 카메라로 사람이 지금보다 크게(`world.fitFixedCamera` 기존 함수 사용).
- 지금 `ch2/scene.js`가 돌려주는 객체(`ladders`·`captives`·`field`·`stairs`·`ring` 등)는 `chapter.js`와 `tests/ch2.test.js`가 쓰므로, **바꾸면 테스트·chapter를 같이 고친다**(아래 3절).

### 2-8. 성능 목표 (시안 놀이 화면 807회가 문제)
- **놀이 화면 그리기 호출 상한: 500회 이하**(`?perf=1` 측정판, 화질 '보통', 1000×560). 시안 807은 사람·성벽·소품이 낱개로 그려지는 탓이므로:
  - **서 있는 무리**(성벽 위 구경 병사, 성안 백성, 거란 대기 병사)는 움직이지 않으면 **굳히기**(`core/bake.js` 방식: 재질별 합치기). `buildScene`이 돌려주는 객체에 넣은 것은 굳혀지지 않으니, 움직이는 사람(병사 아이콘 대응 인물, 사다리 오르는 병사, 구출 무리)만 반환 객체에 두고 나머지는 두지 않는다.
  - 먼 장식에 `userData.minQuality: 'medium'`.
  - 같은 모양(여장·기와·장독)은 합치거나 인스턴스(`core/props.js` 방식).
- 탐험 화면 상한도 같은 500 이하를 목표(측정해 보고 못 맞추면 원인과 현재 값을 보고).
- **금지**: 그림자 해상도, 선명도 배율, 풀·나무 수, 화질 단계 값 변경(측정 전). 윤곽선·입자는 켜지 않는다(측정 뒤 안건).
- 측정 결과(탐험·1파·구출 각각 그리기 횟수·FPS)를 보고에 적는다(소프트웨어 렌더링은 FPS 의미가 약하니 그리기 횟수 중심).

### 2-9. 사실·연출 지침 (검토 대상)
- 모든 사실 문장은 지금 `ch2/script.js`의 것과 출처(S2·S3·S14·S15·S66)를 그대로. **새 사실 문장 추가 금지**. 놀이 안 말풍선은 지금 문장을 짧게 쪼갠 것만.
- 놀이 규칙(병사 배치, 큰 사다리는 병사 둘)은 게임 장치임을 안내문에 사실처럼 쓰지 않는다.
- 불길·피 없음. 사다리·병사·백성 표현은 먼지·물러남·걸음만. 사건 결과(흥화진 함락 못 함, 현종 약속 후 철수, 양규 전사)는 놀이 결과로 바뀌지 않는다.

## 4. 완료 조건
1. `?debug=ch2-scene`·`explore`·`minigame`·`quiz`가 모두 동작하고 장이 처음부터 끝까지(해설→탐험→놀이→퀴즈→도장) **터치만으로** 완주된다(봇 테스트).
2. 성벽 지휘판 3파와 구출 호위가 규칙대로 동작: 파 실패 시 그 파만 다시, **두 번 실패하면 쉬운 모드**, 3파 성공 시 거란군 물러남, 호위 성공 판정(네 무리 이상, 쉬운 모드는 완화).
3. 이어하기: 중간 단계(`minigame`·`quiz`)에서 장면이 맞게 복원(지금 `enterStage` 동작 유지). 옛 저장(진행 중이던 ch2)도 이어짐.
4. 필수 대사 7줄 이하, 한 번에 2줄 이하, 사실 문장·출처·퀴즈 문장은 지금과 같음(`core/content.js` 검사 통과).
5. 그리기 호출: 놀이 화면 500회 이하(측정 보고), 서 있는 무리 굳히기 적용. 화질 값 불변.
6. 한 장 시간 추정 12분 이내(대사 줄이고 놀이 2개 합 4분 30초 안팎).
7. 전체 테스트 통과(고려 1·3~6장, 조선·근대·일제·현대 포함, 회귀 없음).

- 새로 쓸 테스트(먼저 쓰고 실패 확인 후 구현): 구역 배치 판정, 파 실패 시 그 파만 재시도, 두 번 실패 시 쉬운 모드, 호위 성공·무리 놓침, 이어하기 복원, 대사 줄 수 ≤ 7(필수 대사 배열 길이 검사), 놀이 화면 그리기 호출 상한(측정 가능한 범위에서, 시안 테스트의 `drawPieces` 방식 참고).
- 화면 확인: 1000×560에서 탐험·1파·구출·도장 화면을 찍어 사람 크기·버튼 위치·밝기 확인(선생님 확인용 스크린샷 4장 이상).
- `?perf=1`로 그리기 횟수 측정(탐험·1파·구출).

## 7. 검토 필요성: **필수(범위 한정)**
이유: 역사 사실 장면을 새로 구현하고 공통 틀을 정하는 시범이다. 단 **바뀐 부분 중 사실이 걸리는 것만** 본다.
- (역사) 놀이 안 말풍선·안내문·안내판·마무리 대사가 `ch2/script.js` 원 문장과 출처(S2·S3·S14·S15·S66)와 어긋나지 않는지. 쪼갠 문장이 의미를 바꾸지 않았는지(예: 현종 약속 후 철수, 양규 전사, 곽주 탈환 서술).
- (역사) 호위 놀이가 "양규가 물러가는 거란군을 공격해 끌려가던 많은 백성을 구했다"(S15)를 넘어서는 새 사실(구체 인원·지명·전술)을 암시하지 않는지.
- (역사·표현) 병사·사다리 놀이 연출이 불길·피 없이 사건 결과(함락 못 함)를 바꾸지 않는지.
- (고증) 시안 성벽·옹성·망루 표현은 review-2 4절 지침(총안 없음, 단순화)을 지켰는지, 거란 병사가 고려 병사와 확실히 다르게 보이는지.
- (공통 엔진) `runWithRetries` 2번째 실패 쉬운 모드 옵션, 굳히기 규칙 변경이 다른 장에 회귀를 주지 않는지(테스트 결과로 확인, 코드 전체 재검토 아님).
- 검토 제외: 문구 오타, 버튼 위치·크기(레이아웃 테스트가 검사).
