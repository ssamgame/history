## 1. 수정 목표
3장(`ch3`)을 1·2장과 같은 틀(지킴이 · 머리 위 말풍선 · 두 번 틀리면 쉬워짐 · 도장 + 지혜 카드 · 역사책 없음)로 다시 짓고, 지금의 "버튼 한 번" 두 개를 **놀이 ① 둑 수위 조절(`damflow`)** 과 **놀이 ② 귀주 신호(`signal`)** 로 바꾼다. 필수 대사 7줄 이하, 한 장 12분 이내.

## 2. 수정 항목

### 2-1. 흐름 (단계 이름 `intro/explore/minigame/quiz`와 저장 호환 그대로)
출정 카드(해설 2줄, 지금 `intro` 그대로) → 작전 준비(진영 탐험 + **쇠가죽 6묶음 줍기**, ≤2.5분) → **놀이 ① 둑 수위 조절**(≈2.5분) → 물결 연출 → **놀이 ② 귀주 신호**(≈2분) → 귀주 대첩 연출(지금 `playGujuBattle`, 약 7초) → 퀴즈 2문항 → 도장 · 지혜 카드(`finale`).
- 결정: 쇠가죽 줍기(걷기)는 **놀이가 아니라 작전 준비**로 둔다(지금 `collectHides` 그대로, 놀이 2개 원칙 유지). 놀이 ①은 줍기 뒤부터.
- 결정: 지킴이는 1장에서 이미 골랐다. 3장은 `savedGuardian('goryeo-game:guardian','a')` + `usePlayerFigure(world, guardianLook(id,'soldier'))`로 **입기만** 한다(고르기 화면은 2장 방식처럼 저장이 없을 때만 띄운다).
- 역사책 없음. 설명은 말풍선 · 퀴즈 해설로만. 안내판은 새로 만들지 않는다.

### 2-2. 작전 준비 (탐험)
- 강감찬(총사령관, S3·S5) → 병사 순서로 말 걸기, 이어서 쇠가죽 6묶음을 모아 둑(빛나는 원)으로. 대화는 모두 `ops.talk` 말풍선(한 번에 2줄 이하).
- 필수 대사 **7줄**(정의: 반드시 듣는 말풍선 줄 수, 출정 카드 2줄과 놀이 안 안내문 제외): 강감찬 1 + 병사 1 + 놀이 ① 끝 해설 1(`dam.done`) + 돌격 1(`guju.charge`) + 귀주 해설 1(`guju.done`) + 결과 2(`result`).
- 줄이는 법(결정): `start`(안내 1줄) 뺌 → 목표 글자가 대신함. `gangamchan.first` 2줄 → **1줄**(앞 문장만, `src: ['S3','S5']`, 둘째 줄 "병사에게 가서…"는 목표 글자로). `soldier.first` 2줄 → **1줄**(둘째 문장 "진영 곳곳에 쇠가죽…"은 놀이 안내문으로). `hides.built`·`guju.intro`(안내 `guide`)는 뺀다. `later/tooEarly` 줄은 선택(필수 아님).

### 2-3. 놀이 ① 「둑 수위 조절」(`damflow`, 새 부품)
**규칙(결정)**
- 둑 위쪽에 쇠가죽 둑이 서 있고 냇물 둑 뒤에 물이 모인다. 위 가운데 **물 높이 막대**(세로, 눈금 3칸)가 보인다(`opsGauge` 방식 CSS를 `damflow.js`가 스스로 넣음).
- 화면 아래 큰 단추 **「물 모으기」를 누르고 있으면** 물 높이가 차오르고(꽉 차는 데 4초), **떼면 둑이 터진다.** 넘치도록(꽉 찬 채 1초) 누르고 있으면 저절로 터진다 = 실패(너무 일찍 터진 것과 같이 처리).
- 거란군이 냇물을 건너는 줄이 위에서 보이고, 성공 조건은 **둘 다**:
  ① 떼는 때에 거란군 무리의 가운데가 냇물 한가운데(지금 `DAM_WINDOW` 0.5~0.82, 쉬운 모드 0.42~0.88),
  ② 물 높이가 **2칸 이상**(쉬운 모드 1칸 이상, 눈금 위에 성공 칸이 반짝이는 표시).
- 실패 힌트(기존 문장 재사용): 일찍 → `dam.early`, 늦음 → `dam.late`, 물이 모자람 → 새 안내문 한 줄 "물이 아직 모자라요. 조금 더 모았다가 놓아요."(안내 `guide`, 사실 아님).
- 건너는 시간: `CROSS_SECONDS` 10 → **12**(물 모으는 시간이 필요해서). 쉬운 모드는 성공 칸 반짝임 + 두 번 실패 뒤 적용(`runRounds`의 `easyAfter: 2`).
- 연출: 성공하면 물결이 하류로 쏟아지고 거란군이 휩쓸림(지금 `playFlood`). 물 높이에 따라 둑 뒤 물색이 점점 올라온다. 불길 · 피 없음.
- 사실 경계: 물을 막았다 터뜨린 일은 **흥화진 앞 냇물, 1018년 12월**(S3·S5). 귀주 대첩은 **1019년 2월 귀주**(S5)로 **다른 장소 · 때**다. 해설이 둘을 한 사건으로 읽히게 쓰지 않는다(연출 전환 때 화면에 "다음 해, 귀주"를 쓰지 않아도, 장면 이동 효과(`ctx.fade`)와 놀이 ② 목표 글자는 "귀주 벌판"으로).

### 2-4. 놀이 ② 「귀주 신호」(`signal`, 새 부품)
**규칙(결정)**
- 귀주 벌판 고정 카메라(지금 `gujuCam`). 화면 위에 신호등처럼 **두 표시** 「지원군」 「깃발」이 있고, 처음엔 꺼져 있다.
- ① **지원군**: 김종현의 지원군이 지평선에서 다가오다 도착하면 「지원군」이 켜진다(지금 `reinforcements`).
- ② **깃발**: 바람이 남쪽에서 불어와 깃발이 북쪽을 가리키면 「깃발」이 켜진다(지금 `setFlags(true)`).
- 두 표시가 **같이 켜져 있는 동안**(평소 3초, 쉬운 모드 5초) **「공격 신호」 단추**를 누르면 성공. 하나만 켜진 때 누르면 실패(안내문: "아직 신호가 하나뿐이에요. 두 신호가 같이 켜질 때 눌러요.").
- 순서(결정): 지원군이 먼저 도착하고 **1~1.5초 뒤 깃발**이 켜진다(두 번 시도 사이에 무작위, 지금 `gujuSeed` 방식). 깃발이 먼저 흔들리다 마는 가짜 바람은 넣지 않는다(S5: 바람은 무작위가 아니라 남쪽에서 분 것).
- 안내문(`guju.howto`)은 사실 주장을 새로 만들지 않고 지금 문장("김종현의 지원군이 오고 깃발이 북쪽으로 휘날리는 순간")을 줄여 쓴다(안내 `guide`, 사실은 S5 문장과 같은 뜻).
- 성공하면 강감찬 돌격 대사(`guju.charge`) → 지금 `playGujuBattle`(7초) → 거란군 쓰러짐 · 달아남은 지금 연출 그대로(불길 없음).
- 기록: 두 놀이 각각 `firstTryCorrect/Total`(한 번에 성공했는지), 합쳐 `{ firstTryCorrect, firstTryTotal: 2, easyModeUsed }` 지금 형식 그대로.

**부품 위치(결정)**: 새 파일 `chapters/kit/damflow.js`(`export function damflow(ctx, { window, easyWindow, crossSeconds, minLevel, easyMinLevel, scene })`)와 `chapters/kit/signal.js`(`export function signal(ctx, { lights, open, easyOpen, scene })`). 기존 `chapters/kit/*`와 `ops.js`는 바꾸지 않고 `ops.js`의 `runRounds · talk · popText · shake · finale · savedGuardian · usePlayerFigure`를 import해서만 쓴다. 단추는 `core/minigame.js`의 `actionButton`을 쓰지 말고(눌러 떼기 필요) `damflow.js`가 직접 만든 터치 · 키보드(스페이스 누르기 · 떼기) 단추를 쓴다. CSS id는 `kit-damflow-style`, `kit-signal-style`. 새 파일이므로 배포 때 `PRECACHE`에 넣는다(마지막에 개발, 판 번호는 승인 뒤).
- `signal.js`는 켜진 표시 두 개와 단추만 맡고, 지원군 · 깃발 움직임은 `chapters/ch3/scene.js`의 `reinforcements · setFlags`를 장 쪽이 콜백(`scene.on(i)`)으로 부른다(부품이 장면을 직접 만지지 않음).

### 2-6. 장면 · 그래픽 (새 그래픽 결정 없음)

## 4. 함께 고칠 것 — 1장 강동 6주 기둥 (결정)
**문제**: 1장 담판 뒤 연출(`chapters/ch1/scene.js`의 `pillars`, 속이 빈 노란 원통 6개 · 투명 0.35)이 **멀리서 하얀 빛줄기**처럼 보인다(확인 스크린샷 `/tmp/claude-0/-home-user-history/13ae0d24-d82d-54ca-8f87-2bf31d04e2c0/scratchpad/ch1/v5-pillars1.png`).
**처리**
- 빛기둥을 **작은 성채 표시**로 바꾼다: 성벽 한 칸(낮은 사각 기단 + 여장 없는 단순한 성벽 + 작은 망루 하나) + 꼭대기 깃발, 땅에서 **솟아오르는**(scale.y 0→1) 연출은 그대로 쓰되 투명 원통은 쓰지 않는다. 크기는 한 칸이 화면에서 **높이 약 40px 이상** 읽히게(멀리서도 모양이 보이게).
- 이름표(`labelSprite`)는 지금처럼 완성되면(k>=1) 보이게 하고, 글자가 모양과 겹치지 않게 위쪽에.
- **새 공용 부품**: `chapters/goryeo/set.js`에 `castleMarker({ color, flagColor })`를 **추가만** 한다(기존 `cityWall · watchtower · flag` 재사용, 기존 함수 수정 금지). 1장이 쓰고, 새 4장(`ch7`) 9성 표시도 같은 부품을 쓴다.
- 1장 `pillars[i].set(k)` 인터페이스와 `gangdongPillars` 이름은 유지(`chapters/ch1/chapter.js` · `tests/ch1.test.js`의 "6개 스프라이트" 검사 영향: 라벨 스프라이트 6개 유지).
- 위치: 6주 자리(`x = -25 + i*10, z = -42 - (i%2)*4`)가 카메라에서 멀면 가까이 당기거나 크기 키움. 확인은 `?debug=ch1-minigame` 끝 연출 스크린샷.
- 담당: `chapters/ch1/scene.js`(개발이 이미 1장을 끝냈으므로 이 부분만 다시 연다), `chapters/goryeo/set.js`(추가), `tests/ch1.test.js`(스프라이트 6개 · 모양 존재 검사 갱신). 이 항목은 3장 개발이 함께 하되 3장 파일과 겹치지 않는다.
